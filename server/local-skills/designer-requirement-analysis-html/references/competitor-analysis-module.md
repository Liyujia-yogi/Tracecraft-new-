# 第三模块：同类功能竞品分析

## 目标

分析需求中出现的同类功能在主流云产品中的页面与交互表现，为设计师提供可核查的设计参考，不把竞品做法写成本品需求。

固定范围：

- 本品：移动云。
- 竞品：阿里云、华为云、腾讯云。
- 可使用 `$product-prototype` 辅助识别功能、页面、角色和业务路径。

## 执行步骤

1. 从需求索引和页面详情中提取需要研究的“功能单元”，例如创建、编辑、关联、配额选择、异步任务或高风险删除。
2. 为每个功能单元建立同口径比较维度。
3. 检索当前公开可访问的产品文档、帮助中心、控制台说明或可信截图。
4. 记录产品、功能、页面/入口、证据 URL、访问日期、证据状态和关键事实。
5. 将竞品事实与设计启示分开；设计启示只说明“可参考什么、为什么”，不得写成移动云已经确定的规则。
6. 无法访问登录后控制台时，明确写 `登录受限`；只有文档证据时写 `文档证据`；无可靠证据时写 `待补证`。

## 固定比较维度

- 产品入口与导航位置。
- 页面结构和信息层级。
- 页面载体：独立页、抽屉、弹窗、向导或内嵌区块。
- 字段、默认值、必填、校验、禁用和错误提示。
- 主要流程、分支、取消、返回和回退。
- 成功、失败、异步、部分成功和状态反馈。
- 配额、地域、可用区、权限、版本和关联资源限制。
- 删除、覆盖、迁移、解绑等高风险操作保护。
- 列表、详情、选择器和多入口之间的一致性。
- 与需求直接相关的特色能力和明显缺口。

## 证据规则

- 每条可验证事实必须附 URL 和访问日期。
- 标记证据状态：`verified`、`docs-only`、`login-blocked`、`inaccessible`、`not-found`。
- 不凭模型记忆写“当前产品就是如此”。
- 不用营销页的笼统表述代替具体交互证据。
- 不确定时保留阻塞说明，不强行做优劣结论。
- 截图证据写明截图来源和页面日期；不得把第三方旧截图当成当前控制台事实。

## 输出结构

### 1. 功能范围

列出本次需求对应的竞品功能单元、关联页面和 `Rxxx` 来源。

### 2. 总体对比表

| 功能单元 | 移动云需求事实 | 阿里云 | 华为云 | 腾讯云 | 设计启示 |
|---|---|---|---|---|---|

移动云列只写本次需求事实或“需求未定义”，不能用竞品信息补写。

### 3. 分功能证据卡

每个功能单元按产品输出：

- 产品名称。
- 入口与页面。
- 页面结构和字段/校验。
- 流程与状态反馈。
- 风险保护。
- 证据 URL。
- 访问日期。
- 证据状态。
- 与本需求的相关性。

### 4. 设计启示

按以下标签分类：

- 可直接参考的表达模式。
- 需要结合移动云规则再决定的模式。
- 竞品之间没有一致做法的争议点。
- 证据不足、需要产品或设计进一步验证的内容。

### 5. 证据与阻塞清单

列出全部来源、访问日期、证据状态、受阻原因及仍缺少的证据。

## 禁止事项

- 禁止只写一段泛化竞品总结。
- 禁止遗漏阿里云、华为云或腾讯云；没有证据也要保留对应空状态。
- 禁止把竞品字段或流程直接写成移动云既定方案。
- 禁止只比较视觉风格而忽略规则、状态反馈和风险保护。
- 禁止无来源优劣排名。
