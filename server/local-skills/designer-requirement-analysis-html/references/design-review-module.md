# 第二模块：设计要点与设计风险

## 目录

1. 目标
2. 输入与去重边界
3. 设计师关注范围
4. 核心原则
5. 执行流程
6. 汇总规则与风险补漏
7. 最终输出结构

## 1. 目标

把真正影响设计方案的内容整理为设计师可快速核对和评审的结论，只回答：

1. 哪些规则需要在多个页面保持一致？
2. 哪些问题不确认，设计无法定稿？
3. 各页面有哪些必须关注的设计要点和设计风险，哪些风险需要重点评审？
4. 哪些产品术语需要统一？

不要重复需求背景、业务流程、页面字段和页面操作说明。

## 2. 输入与去重边界

优先读取：

- 原始需求文档。
- `requirement_source_indexed.md`。
- 已生成的需求总览、业务流程、页面流程和页面详情。
- 页面级待确认项、设计要点和设计风险。
- 风险知识库 `knowleddge`。
- IP 兜底知识库 `fallback-kb`。

### 2.1 不重复展示

- 需求概述、目标用户、使用场景和页面数量。
- 业务泳道图、主要/分支流程和 A-F 层分解。
- 页面层级、页面流程、页面模块和跳转关系。
- 页面清单。
- 页面所属模块、路径、类型、前置条件、字段、必填、默认值、限制、交互规则、操作流程、成功/失败/异步反馈和已明确的页面级待确认项。
- 同类功能竞品分析。
- React Flow、ELK.js、Mermaid、Graphviz 等实现技术。

### 2.2 强制重复的例外

“全部页面的设计要点与设计风险”不执行上游去重。必须完整收录上游每个页面的：

- 页面设计要点。
- 页面设计风险。
- 与风险直接相关的设计保护建议。
- 影响设计评审的关键交互问题。

必须按页面归类，不只挑高风险页面；保留原意；只有表达和设计动作完全重复时才允许合并，并列出全部受影响页面；新补充风险与上游内容分开。

### 2.3 可重新归纳

同一问题在页面详情中出现，但满足以下任一条件时可在本模块重新归纳，并说明全局影响：

- 影响两个及以上页面。
- 影响创建、编辑、删除、关联等多个操作。
- 决定全局页面结构或统一交互模式。
- 风险影响整个产品而非单页。
- 多个页面待确认项实为同一个产品决策。

## 3. 设计师关注范围

只保留直接影响以下事项的信息：

- 页面结构和信息层级。
- 操作入口和操作路径。
- 字段联动、禁用、校验和错误反馈。
- 状态表达和结果反馈。
- 高风险操作保护。
- 多页面一致性。
- 设计能否定稿和进入评审。

删除：

- 纯后端接口、数据库、算法、任务调度和技术架构。
- 不影响界面设计的数据处理过程。
- 产品背景、市场目标、运营指标和项目管理信息。
- 已在页面详情完整说明的字段和流程，但页面设计要点和风险仍须汇总。
- “按钮使用主色”“遵循平台规范”等通用常识。
- 没有具体设计动作的泛化风险。
- 竞品信息和前端渲染方案。

技术规则若影响界面，只写设计影响，不展开实现。

## 4. 核心原则

### 4.1 来源可追溯

- 单条来源：`← R023`
- 连续来源：`← R023-R026`
- 多条来源：`← R023, R043`
- 风险库：`← 风险库建议：knowleddge/条目ID`
- 兜底知识：`← 兜底建议：fallback-kb/条目ID`
- 需求推导：`← 设计推导，基于 Rxxx`

不得把知识库建议写成需求事实。

### 4.2 事实、缺口、建议分开

统一顺序：需求事实 → 对设计的影响 → 需要确认或采取的设计动作。

示例：需求明确资源关联后立即生效，但未说明生效前是否校验现有配置。该规则可能影响创建页、详情页和关联弹窗，需要确认是否增加配置检查和影响范围确认。`← R023-R024`

### 4.3 不凑数量

- 全局阻塞问题最多 5 条。
- 跨页面设计约束最多 6 条。
- 逐页面设计要点和风险不限数量，以完整覆盖为优先。
- 新补充风险只保留有明确设计影响的内容。
- 术语只收录真实存在的不一致。
- 没有符合项时允许章节为空；最终 HTML 不展示空章节。

## 5. 执行流程

### 步骤 1：建立已展示内容清单

记录已展示页面、字段、交互、待确认项、页面级设计要点和风险、所属页面及产品术语。页面级要点和风险不用于删除，而用于步骤 5 的完整汇总。

### 步骤 2：内部执行完整性检查

检查创建/查看/编辑/删除，关联/移除/启用/停用，导入/导出/批量操作，以及立即生效/异步执行/部分成功/失败结果。该检查只用于发现遗漏，不输出机械 CRUD 表或页面清单。发现页面缺失时回补第一模块。

### 步骤 3：提炼跨页面设计约束

只保留至少影响两个页面或多个操作的规则，例如：

- 同一资源在列表、详情和选择器中的状态一致。
- 同一互斥规则在创建和编辑中统一处理。
- 默认规则或系统对象在不同页面统一表达。
- 同一高风险操作在多个入口使用一致保护。
- 地域、可用区、版本和权限限制在多个选择器中一致。

页面内单一字段规则不重复。输出表格：

| 跨页面设计约束 | 影响页面/操作 | 设计需统一的内容 | 来源 |
|---|---|---|---|

### 步骤 4：筛选全局阻塞问题

只保留不确认会影响整体方案的问题：

- 页面结构或载体无法确定。
- 核心操作路径无法确定。
- 多页面对同一规则存在不同解释。
- 高风险操作的确认、回滚或影响范围未定义。
- 导入、批量、异步或部分成功缺少统一处理方式。

页面内部可由设计规范直接解决的问题不进入此处。格式：

`需要确认的决策点：可选方案、影响页面和不确认的后果。← Rxxx`

### 步骤 5：汇总全部页面的设计要点与风险

- 不与上游去重，也不限于 P0/P1。
- 覆盖第一模块全部页面。
- 每个页面的要点、风险和保护建议全部收录。
- 普通但影响设计和评审的内容同样保留。
- 上游无相关内容的页面明确写“上游未总结相关内容”。

### 步骤 6：统一术语

只收录界面可见且确有不一致的导航/标题、资源名称、按钮、状态和方向、中英文/缩写、关联/绑定和移除/解绑等动作词。纯接口、数据库和后台技术名词不收录。

| 需求中的不同用词 | 统一用词 | 使用位置 | 来源 |
|---|---|---|---|

### 步骤 7：去重和压缩

除步骤 5 的上游页面要点和风险外，依次判断：是否已展示、是否直接影响设计、是否影响多个页面或核心操作、是否需要设计师/PM 决策、是否有明确来源、是否能转化为具体动作。不满足直接影响、多页面/核心操作、需决策、明确来源中的任一项则删除。步骤 5 以完整收录为优先，不适用此删除规则。

## 6. 汇总规则与风险补漏

### 6.1 分类

- 设计要点：影响布局、字段表达、交互、状态反馈或操作路径。
- 设计风险：可能造成误解、误操作、业务中断、数据错误、状态不一致或结果不可感知。
- 补充风险：上游未总结，但从原文、`knowleddge` 或 `fallback-kb` 发现。

### 6.2 合并规则

- 按第一模块页面顺序组织。
- 每条保留所属页面。
- 同一风险影响多页可合并，但列出所有页面。
- 只有文字完全重复且设计动作完全一致时合并。
- 合并不得减少风险含义、触发条件或设计要求。
- 上游内容和新增内容分开标记。

### 6.3 补充风险检查

检查：

- 默认行为与用户预期不一致。
- 立即生效但缺少影响范围确认。
- 删除、覆盖、迁移或切换不可逆。
- 批量、导入或异步操作存在部分成功。
- 多入口造成状态或结果不一致。
- 禁用、过滤、置灰和错误提示未统一。
- 高风险操作缺少操作前、操作中、操作后的保护闭环。

补充风险必须使用需求推导、风险库或兜底知识来源格式。

### 6.4 页面汇总表

| 页面 | 类型 | 设计要点/风险 | 对设计的影响 | 设计处理建议 | 来源 | 内容来源 |
|---|---|---|---|---|---|---|

`类型` 为设计要点、设计风险或补充风险；`内容来源` 为上游需求详情、需求推导、`knowleddge` 或 `fallback-kb`。建议不能伪装成确定行为。

高风险项补充完整闭环：触发条件 → 用户可能的误解或误操作 → 操作前保护 → 操作中限制 → 操作后反馈。
